# 启动调用门与数据语义契约

用于新题求解、完整论文生成和接续他人项目。目标是先取得足够条件，再进入目标模式；不要把训练记忆或历年惯例当作当前赛题证据。

## 1. 先检查已提供材料

先读取用户给出的路径，确认实际存在的题面、补充说明、附件、格式规范、已有代码和已有结果。不要因为文件名像赛题或优秀论文就假定内容、年份和题号正确；资料进入方法检索或优秀论文对照前，至少核对标题、比赛、年份、题号和主题。

任务简报开头同时写明：当前任务属于数学建模竞赛，用户身份是参赛者或参赛队，目标读者是竞赛评委。这是写作与取舍的基础背景，不是免除问询的默认授权。

## 2. 硬暂停状态门

状态只按 `待确认 -> 等待用户回复 -> 可执行` 单向转换，不能由执行者自行跨越。

新题首次调用先做只读材料核对，再判断当前消息是否已经明确给出下面全部答案。若没有，进入 `等待用户回复` 状态：集中问一次并结束当前回复。此时不得开始问题拆解、模型选择、数据计算、代码生成、论文目录或正文写作，也不得在提问后继续调用执行工具。

只有两种方式可以进入 `可执行` 状态：

1. 用户逐项回答；
2. 用户明确回复“默认”或“全部默认”，表示接受列出的默认选项。

静默、未选择、用户只说“开始做/直接完成/生成论文”，都不构成默认授权。不得替用户把未回答项补成默认值。若用户在首次消息中已经逐项给出全部答案，或明确写了“其余全部默认”，可以直接进入 `可执行` 状态，不必机械追问。

集中问询提供“默认”选项，但默认值只在用户明确选择后生效，不连续追问零散偏好。

必选项：

- 正文页数上限；用户回复“默认”时采用正文30—40页，但当届官方上限优先。
- 交付范围：方案、代码、结果工件、论文或完整交付。
- 题面、附件和格式规范是否已全部提供；未提供的项目登记为缺失或待核实。

同时主动提供可选项：

- 写作风格：简洁竞赛型、理论推导型、数据分析型、图表展示型；
- 文章重点：模型创新、可靠性验证、决策建议、可解释性；
- 方法偏好或禁用方法、公式深度、图表密度、附录规模；
- 目标层级、剩余时间和可用计算环境。

用户明确回复“默认”或“全部默认”时，采用：正文30—40页（当届官方上限优先）、完整交付、简洁竞赛型、可靠性与完整闭环优先，模型复杂度由样本外证据决定。把用户回答原文或可定位的确认记录写入任务简报，并注明来源为用户、官方文件或用户明确接受的默认值。

正文页数的默认统计范围为摘要起至结论/模型评价止，不含封面、目录、参考文献、附录和源码；用户或官方采用其他口径时明确记录。

首轮允许输出的内容仅限：已核对材料的简短状态、需要用户回答的一组问题、可选答案及默认含义。问题之后立即结束回复。

## 3. 证据准入等级

- **完整题面+必要附件**：可进入数据建模和完整论文模式。
- **只有题面、没有必要附件**：可做问题拆解、候选模型和代码框架；不得编造数据统计、拟合结果或完整实证论文。
- **格式规范缺失或损坏**：内容工作可继续，但相关要求只能标“待核实”；不得凭往届经验写成当届硬约束。
- **接续已有项目**：先区分已有作者主张、程序输出、独立复算和科学验证；审计报告只作线索。

## 4. 数据语义契约

在写业务清洗和选择模型前，用少量样本行、字段取值和题面定义回答：

1. 一行是什么：独立对象、同一对象的一次观测、时间窗、空间点还是重复检测？
2. 独立单位是什么：切分、重采样、标准误和最终决策分别在哪个层级？
3. 标签属于哪一层：记录、对象、时间段还是事件？同一对象标签冲突时如何解释？
4. 事件时间是什么：准确发生时间、首次被观察到，还是两次观测之间的潜在时间？
5. 观察过程是什么：观测时点是否由病情、设备、人工安排或历史结果决定？
6. 变量是否随时间变化：记录级数值、个体基线值和个体内变化是否被混用？
7. 决策时能看到什么：结局后变量、全期统计量和未来观测必须封存。

这份契约与样本单位、信息时点、评价契约一同冻结。发现定义变化时，先记录影响，再重跑受影响结果，不能只改正文解释。

## 5. 阻断条件

出现以下任一情况时，暂停数据结论并先解决语义：

- 同一对象多条记录，却按行随机切分；
- 大多数事件在首次观测时已经发生，却被当作准确事件时间；
- 同一对象标签大量混合，却没有定义标签属于记录还是对象；
- 动态变量被解释为固定个体属性；
- 观测安排可能影响“首次发现时间”，却按自然发生时间解释。

优化类赛题另见 `optimization-integrity.md`；其中与状态门同级的一条：**不得因求解结果不理想而取消或放宽题面硬约束**。供需缺口应如实报告，重构或松弛模型与原题结果分开；下游问题运行前，上游方案必须先通过硬约束复核。
