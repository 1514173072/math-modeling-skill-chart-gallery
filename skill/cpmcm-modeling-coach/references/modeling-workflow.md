# 竞赛建模工作流

## 第0步：规则与交付契约

先按 `preflight-and-data-semantics.md` 检查材料并完成硬暂停状态门。集中确认正文页数、交付范围以及风格/重点等可选项；当前消息未明确回答全部启动问题时，首轮提问后立即结束，不得以默认模板继续。只有用户逐项回答或明确接受默认值后，才形成带来源的任务简报并进入后续步骤。未取得真实题面和必要附件时，不进入数据结论或完整论文模式。

任务简报显式登记“数学建模竞赛、参赛者/参赛队、竞赛评委”三项背景，使后续方法取舍、表达密度和交付物始终面向竞赛，而不是默认写成教程或通用分析报告。

读取当届题面、补充说明、数据附件和提交规范，形成硬约束清单：文件格式、匿名要求、页数或大小、命名、截止时间、代码/数据/AI使用声明等。竞赛官方要求高于本Skill、课件和历年论文的惯例；无法确认的要求标为待核实，不凭往届经验补全。

同时填写 `references/reproduction-audit.md` 的样本单位、数据语义与观察过程、信息时点、评价四份契约。先冻结每问要交付的数值、图表、文件和验证，再选模型。

## 审题与任务契约

逐小问登记输入、未知量、输出形式、评价指标、硬约束、软目标、时空尺度和信息可用时点。更正说明与原题同等优先。先列不可直接观测的潜变量和额外假设。题面指定“基于X”时，将X记为核心输入；若加入目标历史或其他在线状态以完成动态预测，另记为扩展输入，并用消融报告X的增量贡献，避免悄悄改变题意。

在候选方法前形成五维问题画像：任务目标、数据结构、不确定性来源、决策约束、证据与计算预算。对于跨小问混合任务，明确每层的输入输出，例如 `原始观测 -> 状态估计 -> 预测/评价 -> 优化决策`，并分别设置验收门。

## 数据与证据

先从实际文件导出列名、类型、少量原始值、唯一值和缺失编码，再建立字段字典、单位表、缺失机制、样本独立单元和时间可用性表。冻结标签归属层级、事件发生与观察方式、动态/固定变量口径。按需执行 `eda-protocol.md` 中的结构、质量、时序与污染传播检查。按真实部署方式划分：时间序列采用滚动起点，空间任务采用留区验证，同对象多切片按对象分组。预处理、筛选和调参只在训练折内完成。

同时判断不确定性属于可抽样随机性、语言模糊、灰色贫信息、参数区间还是模型结构未知。该判断决定概率模型、模糊方法、灰色方法、情景/鲁棒方法的入口；不得用一种“综合不确定性权重”替代不同来源的建模与验证。

## 模型链

每个小问至少给一个透明基线，再根据证据决定是否升级：

`原始输入 -> 状态/特征 -> 模型 -> 中间量 -> 决策/预测 -> 验证`

比较假设、可识别性、计算成本、数据量、外推风险与可解释性，不按模型新旧排序。复杂模型没有稳定样本外增益时保留基线并解释负结果，不为“每问多个模型”而堆算法。

候选方法表至少登记：方法承担的任务、输入与输出、适用前提、相对基线的预期增益、最低验证、失败条件和切换方案。主方案最多一个；备选方法只有在承担不同假设、偏好或异常情景时保留。评价、预测和优化混合时，前一层结果必须通过接口工件进入下一层。

## 实现与检查

先实现最小闭环，再添加复杂模块。保存随机种子、版本、参数、数据切分和中间结果。对守恒式、约束、单位、边界和目标函数做独立断言；优化同时报告可行性残差、运行时间和最优间隙（若可得）。涉及选址、分配、定价、调度或多目标时执行 `optimization-integrity.md`：先冻结硬约束、定义、原始目标和补充假设，假设不得因结果不理想而取消硬约束。

小问存在依赖时，跨问调用必须经过可读取的接口工件，而不只在文字中“承接前问”。通用字段是Schema、输入输出单位、来源、版本和有效域；特征顺序、系数/权重、预处理、时滞/平滑、随机种子等按模型适用性记录。下游代码真实加载该工件，并以测试断言核对接口语义。

结果先跑后写。为主表、主图和正文数字保存机器可读工件与正式生成脚本；临时命令产出的工件必须回写到明确负责的版本化脚本并全链重跑，否则视为无主工件。主表和关键数字从工件程序化生成，不手抄。给关键数值保留来源键、统计口径、数据切分和生成时间。内部工件一致后，从最终时点、核心显著性、主性能指标和关键优化值中选择会改变结论的少量主张，用不复用作者评价函数的独立实现、标准库或解析恒等式复核。

结果资产 Schema 冻结后，按 `advanced-visualization.md` 建立图表证据契约并查询本地图表库。先写“图要支持什么主张”，再匹配数据契约和已验证模板；模板合成数据必须全部替换。每张主图保留源字段、过滤/聚合/标准化/分箱等变换、生成脚本、关键数值断言和渲染检查记录。没有真实结果或必要中间量时，只登记待生成图及所需 Schema，不输出带真实语气的示例图。

## 验证

预测、分类、阈值、分组、切点和模型选择统一按 `validation-integrity.md` 冻结评价协议。缩放、插补、筛选、重采样、校准、阈值和切点均视为训练/选择过程；不得在评价折外泄后仍称严格OOF。数据驱动选择后的同样本显著性只能标为探索性，除非外层验证覆盖完整选择过程。

- 预测：比较朴素/机制基线，滚动或分组验证，报告误差分布和失败区间。
- 分层长表：同时检查合并口径和组内/逐组分布；若组间水平差可能抬高合并指标，解释差异，并按真实预测/决策单位指定主口径，而不是默认选择较好的一种。
- 分类：检查不平衡指标、校准和对象级泛化。
- 优化：检查全部约束、实际服务流、内生分配、原始目标、基线策略、敏感性、极端情景和计算预算。独立验证模型必须说明覆盖了主体模型的哪些变量、约束和目标；松弛模型只能验证上界或子问题。若控制量在上游模型中弱识别，执行 `weak-identification-optimization.md`，不得把求解器成功当作策略可靠。
- 决策：把“预测优化门”和“现实行动门”分开。前者只说明数据支持域内的模型情景，后者还需要可操纵性、机理/识别与安全证据；未过现实行动门时输出候选策略或验证计划，不称工程最优。
- 仿真：检查数值稳定性、参数敏感性和已知极限；区分模型内结论与现实证据。
- 因果：写明估计目标、处理、结果、混杂、时间顺序、识别假设和敏感性分析。
- 模糊/灰色：检查隶属函数、权重、合成算子、分辨系数、级比或等价可建模性条件及其敏感性；灰色预测必须有滚动外测和透明时序基线。
- 多属性决策：检查硬约束预筛、正向化、标准化、权重来源、补偿规则、排名反转和权重/阈值敏感性；排名不能替代资源配置模型。
- 多元统计：检查变量尺度、保留维数/因子数/簇数的选择边界、载荷解释和重采样稳定性；无标签聚类不报告分类准确率。
- 随机过程与规划：检查分布或过程假设、Monte Carlo误差、MCMC收敛和独立情景下的目标分布、尾部损失与约束违反率。
- 图网络：检查节点/边/权重语义、算法适用条件、连通/守恒/容量/访问残差和目标独立复算。
- PDE与连续场：按 `pde-numerical-modeling.md` 检查控制方程、初边值/界面条件、稳定性、至少三档网格或时间步收敛、内部/边界残差、守恒或已知极限；参数校准与现实验证使用不同数据。
- 几何路径与空间感知：按 `spatial-perception-multimodal.md` 分别验收坐标/拓扑、合法路网、沿途感知代理、综合评分与外部泛化，避免用下游排名掩盖几何错误。

## 写作

按 `paper-writing-protocol.md` 和 `paper-quality-gates.md` 组织全文。摘要形成“问题—方法—结果—验证—价值”闭环，不堆算法名；正文保持符号、数据口径、图表和代码一致；结论只覆盖证据支持的范围。先建立主张—证据矩阵，再从结果工件写作。矩阵必须分开记录内部一致性与科学有效性，不能用“结果文件与正文一致”替代评价协议核验。

生成可阅读初稿后先执行正文页数、引用、图表、语言和代码交付质量门。第一次正文不足时建立缺口矩阵并进行一次证据型扩写；重新渲染仍不足时暂停请示。通过质量门后冻结版本，不立即交付。环境支持子智能体时，独立评审者先从可用语料选择3—5篇相似优秀论文，再按 `competition-paper-review.md` 对照真实题面、附件状态、冻结论文、必要工件和基准论文评审；主执行者只修复有证据的问题，模型或上游工件变化后全链重跑，再做一次定向复核。未解决的核心问题必须披露，不能用润色、工程复现分或总分抵消。

页数、图表数和参考文献数服从 `paper-quality-gates.md`：正文页数使用用户确认口径并设置两轮状态机；完整论文默认至少15篇且通过引用覆盖门；图表按证据角色与可读性筛选。不得为了数量扩写、拆图、复制代码或编造实验。当届规范若有明确要求则严格服从。

## 时间预算

先按剩余时间分级：优先完成“可运行基线—可信验证—可追溯主结果—完整论文”的闭环，再投入复杂模型、额外稳健性和视觉润色。每次升级模型前写明预期增益、最长尝试时间和停止条件；为摘要、交叉核对、格式检查和最终导出预留独立时间。
