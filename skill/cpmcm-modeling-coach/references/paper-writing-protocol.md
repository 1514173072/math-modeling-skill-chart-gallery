# 竞赛论文写作协议

本协议用于把已经完成的建模与实验转化为可追溯论文。完整论文同时执行 `paper-quality-gates.md` 的统一章节、篇幅、语言、图表、引用和代码交付门；当届官方规范始终优先。

## 1. 写作前置输入

先准备五类输入：题面与格式硬约束、逐问问题契约、五维问题画像与候选方法表、机器可读结果资产、主张—证据矩阵。缺少结果资产时先补实验或明确“尚无结果”，不要先写带数字的结论。

结果资产至少能回答：该数值由哪个脚本、数据切分、统计口径和文件字段生成；该图表使用哪个源数据；该结论在哪些情景下不成立。使用 `assets/claim-evidence-matrix-template.md` 登记这些关系。

## 2. 全文结构

- **标题**：体现研究对象和关键任务；方法名只在确实构成主要贡献时进入标题。
- **摘要**：按各小问形成“任务 -> 方法及选择理由 -> 关键定量结果 -> 验证/边界 -> 价值”闭环。不得出现正文没有的结果，不把算法名列表当摘要。
- **问题重述**：用自己的结构重组输入、输出和约束，不机械复制题面，不悄悄改变目标。
- **问题分析**：说明困难、信息流、子问接口和候选路线；文献只服务于选择依据和方法边界。
- **符号与假设**：只列正文实际使用的符号；假设写明必要性、可能偏差和可检验方式。
- **逐问建模求解**：问题契约 -> 机理或预备分析 -> 透明基线 -> 有证据的主模型 -> 求解/算法 -> 结果 -> 验证 -> 局限。并非每问都必须包含机理推导、多个模型或命题证明。
- **总结评价**：区分得到的结果、可迁移价值、局限和改进条件，不把未来计划写成已完成工作。
- **参考文献与附录**：只列真实查阅且正文使用的来源；附录放源码清单与复现入口、长推导、中间表和合规材料，完整源码位于论文PDF之外；支撑主结论的关键结果仍应在正文出现。

## 3. 模型与算法如何写

定义变量、单位、索引和参数来源后再给公式。优化模型依次写决策变量、目标、逐类约束、边界和模型类型；ODE模型写状态、演化方程、初边值条件、参数和数值求解器。

方法选择段先说明问题结构和透明基线，再解释主方案能解决基线的哪一项不足、其前提如何由题面或数据支持，以及何时转向备选或降级。不要按“先AHP、再TOPSIS、再机器学习”的算法顺序拼论文，也不要用“先进、经典、常用”代替选择证据。

模糊/灰色、综合评价、多元统计、随机过程和图网络方法应分别交代其特有对象：隶属函数或生成序列、指标权重与补偿规则、载荷/因子/簇结构、分布/状态/情景、节点/边/容量。任何方法特有参数都要说明来源并进入敏感性或稳定性分析。

算法段说明选择理由、输入输出、关键步骤、停止条件、复杂度或计算预算。只有流程不能由公式和短段落清楚复核时才加伪代码或流程图。重要公式编号并逐项解释；不能从正文追到代码的“黑箱步骤”应补接口或参数说明。

正文代码边界：正文只放与公式一一对应的必要伪代码、流程框和关键参数；完整 Python/R/MATLAB 源程序默认放论文PDF之外的独立源码目录，PDF附录只给文件清单、入口、依赖、输入输出与复现步骤。代码不能替代目标函数、约束、参数来源、信息时点和验证定义；代码行数和附录页数不是质量或创新指标。

## 4. 结果与验证如何写

结果段先回答题目，再解释原因。每个经验、性能或数值主张同时给适用的比较对象、评价单位、切分/情景和不确定性；解析或确定性主张则指向推导、定理条件、残差或可行性证书。只有少量切分下的系数方向或均值稳定时，使用“稳定观测关联”，不能直接升级为“效应已辨识”；没有干预识别时不得写现实“最优调控收益”。复杂模型未稳定超过基线时如实报告，并按 `method-routing.md` 的负结果组织方式收缩结论或改变合理任务尺度。

结果分析按任务选择误差分布、稳定性、灵敏度、收敛性、复杂度、约束残差和失败区间。预测、关联、观测方向、模型情景和现实干预使用不同语言。

评价排序应报告权重或标准化变化下的名次稳定性；灰色预测应报告滚动外测而非只给拟合曲线；MCMC应报告链诊断和后验预测；随机规划应报告独立情景违反率和尾部风险；图网络应报告守恒、容量、访问或连通残差。相关验证没有完成时，正文只能写候选方法或探索性结果。

## 5. 图、表、公式与正文一致性

- 先按 `advanced-visualization.md` 建立图表证据契约，再从结果资产选图；不允许先选择“高级图”后补造数据。
- 表题和图题能独立说明对象、单位、样本/情景和统计口径；是否使用三线表服从当届规范。
- 坐标轴、单位、图例、控制界和关键事件完整；正文必须解释图表承担的证据，不放孤立装饰图。
- 不用截图代替可编辑表格或公式，除非原始材料只能以图像引用并已标明来源。
- 正文中的区间、极值、排序和百分比必须从对应结果资产重新计算，不能凭图形目测抄写。
- 每次结果资产变化后，重新生成图表并运行项目级数值断言，再更新正文。
- 本地图表库的合成 PNG 只作预览，Markdown 模板只作绘图起点；合成数据、示例数值和示例结论不得进入正式论文。

## 6. 扩写与压缩

完整执行 `paper-quality-gates.md` 的两轮篇幅状态机。第一次未达到用户确认下限时建立缺口矩阵，只补真实已有或新运行得到的机理、假设依据、基线、消融、敏感性、失败结果、图表解释、接口工件、引用、局限或复现信息；重新渲染后仍不足时停止最终交付并请用户选择，不能自行降目标。成稿过长时，优先删除重复背景、通用算法教材、不支撑结论的图表和原始代码。

## 7. 交付前独立自迭代

可阅读初稿完成后先冻结为评审版本，不向用户宣称最终完成。按 `independent-paper-iteration.md` 执行完整状态机；环境支持子智能体时，启动一个未参与正文生成的评审者，由其使用 `assets/benchmark-selection-template.md` 从可用语料选择3—5篇相似优秀论文，再按 `competition-paper-review.md` 对照真实题面、冻结论文、必要工件和基准论文评审。作者自审报告可以作为线索，但不能作为通过证据；不要把预期分数、怀疑点或希望得到的结论告诉评审者。

评审者输出总分区间、P0/P1/P2问题、题面或页码/工件证据、修复后潜在分和阻止交付条件。主执行者逐条记录“采纳/部分采纳/不采纳及理由”：

- P0涉及题意、硬约束、泄漏、核心定义或关键复算失败，必须回到最早受影响环节并使全部下游结果作废重跑；
- P1在证据支持时修复，不能只改文字掩盖模型问题；
- P2按时间和用户偏好选择，不为提高表面分数堆图、堆模型或扩页。

修订后由评审者做一次针对P0/P1的定向复核。默认只要求一轮完整评审；仅在仍有核心问题时追加第二轮完整评审，除非用户另有要求，不进入无限“评审—重写”循环。若环境没有子智能体，只能执行并标注作者自审，交付时披露独立评审未完成。

## 8. 交稿前八个问题

1. 目标读者是谁，能否在摘要和图表中迅速找到答案？
2. 实际完成了什么？
3. 为什么选择这条方法链？
4. 结果和失败情景是什么？
5. 理论或方法意义是什么？
6. 实际价值和使用条件是什么？
7. 读者可复用哪些工件或结论？
8. 哪些问题仍未解决，什么证据能推动结论升级？
