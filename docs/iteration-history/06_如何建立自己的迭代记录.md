# 如何建立自己的迭代记录

每次真实使用后，建议只记录能够复用的信息，而不是保存冗长聊天全文。

## 最小记录模板

1. **任务输入**：题目类型、附件、格式要求、篇幅、风格和重点。
2. **首次输出表现**：完成了什么，在哪些关键点失败。
3. **独立评价**：按严重程度列出证据明确的问题。
4. **根因判断**：问题来自缺少信息、规则缺失、执行偏差，还是模型能力边界。
5. **Skill修改**：新增或修改哪条规则、模板、脚本。
6. **回归验证**：原问题是否消失，是否引入新问题。
7. **迁移验证**：在不同题型上能否继续生效。

## 适合写入Skill的内容

- 多次出现且可概括为明确触发条件的问题；
- 能通过步骤、检查表或脚本稳定执行的改进；
- 对不同题型仍有价值的建模与审计规则。

## 不适合直接写入Skill的内容

- 只属于某一道题的具体参数和结论；
- 没有证据支撑的个人偏好；
- 为某一次输出临时添加的大段补丁；
- 无法验证、只会增加调用成本的复杂流程。

建议为每次修改保留版本号、修改原因和验证结果。只有完成新题迁移验证后，才把规则视为稳定能力。
