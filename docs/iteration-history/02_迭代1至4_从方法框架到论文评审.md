# 迭代1至4｜从方法框架到论文评审

## 迭代1：建立通用建模链

先把工作流固定为“读取题面与附件 → 拆分问题 → 明确假设 → 选择模型 → 求解 → 验证 → 写作”，避免只堆叠模型名称。

## 迭代2：用真实A题检验完整交付

真实调用暴露出前置条件不足的问题：Agent未先确认附件、篇幅和输出要求便开始写作，第一版只有14页。补齐材料与条件后，论文扩展到42页。关键经验不是追求页数，而是先建立启动门和证据链。

## 迭代3：引入优秀论文对标

评价维度从“是否写完”扩展为：题意忠实度、模型合理性、求解可信度、验证完整性、图表表达、可复现性和结论边界。

## 迭代4：把失败模式转为规则

把真实审计中反复出现的问题写进Skill，包括附件未读、默认模板直接启动、把程序运行等同于科学验证、结论超出数据证据，以及为了增加篇幅而填充无关内容。
